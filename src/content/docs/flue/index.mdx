## Where Flue Fits

Flue is the conversation-scoped agent execution layer in this architecture. A conversation has a
stable instance identity, accepts messages from application code, and keeps its own durable agent
history. Channel packages provide verified provider ingress that application code mounts explicitly.
Those framework responsibilities are documented in Flue's tagged
[durability guide](https://github.com/withastro/flue/blob/v2.0.3/apps/docs/src/content/docs/guide/durability.md)
and [channels guide](https://github.com/withastro/flue/blob/v2.0.3/apps/docs/src/content/docs/guide/channels.md).

For this site, that makes Flue a good boundary for receiving a Slack delivery, selecting a
tenant-aware conversation, and running a narrowly tooled agent. The existing
[Worker Backend](../worker-backend/index.mdx) and [Events](../events/index.mdx) sections remain the
source for Slack request verification, acknowledgement, and transport mechanics.

:::info[Architecture boundary]
Flue is **not** the canonical store for business records, Slack OAuth installations, or Slack List
ownership. It is also not an arbitrary durable filesystem, a sandbox/file persistence guarantee, or
a general workflow database. Keep those concerns in application-owned stores and services; expose
only narrow, authorized tools to the agent.
:::

Slack messages and Lists are interaction or projection surfaces, not automatic sources of truth.
Use the [Lists](../lists/index.mdx) section for the Lists API contract and
[Data Surfaces](../data-surfaces/index.mdx) for choosing what Slack should display.

## How Claims Are Labeled

This section separates evidence from design advice. Treat these labels as part of the contract:

:::note[Verified fact]
Confirmed against the version-matched primary-source hierarchy on
[Source Map and Versioning](./source-map-and-versioning.mdx). A verified fact still belongs to the
stated version and verification date.
:::

:::info[Inference]
A conclusion derived from verified behavior, but not promised directly by the cited source. Recheck
the premises before relying on it as a hard guarantee.
:::

:::tip[Proposed contract]
A recommended application interface or architecture authored by this site. It is a design proposal,
not an existing Flue, Slack, or Cloudflare API.
:::

:::warning[Unverified behavior]
A claim that primary documentation or repository inspection did not settle. Do not promote it to a
fact without a focused test and recorded evidence.
:::
